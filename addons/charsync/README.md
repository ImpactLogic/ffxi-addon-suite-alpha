# charsync

## Sortie temporary state (0.3.7)

Sortie capture is OFF by default; `//cs sortie on` turns it on.
`sortie-temporary.tsv` is a separate latest client-view capture, and
`sortie-temporary-history.tsv` preserves earlier frames. All33 allowlisted
items retain persistent-traversal versus consumable classifications. Outside
Sortie, failed APIs and incomplete/count-changing reads remain unknown.
Negative observations require a count-consistent scoped read; they never
remove permanent inventory or establish lost unlocks, boss clears or exact
consumption causes. Capture is read-only. Atlas pack/UI import is pending.
After deployment, reload with `//lua r charsync`; offline checks do not verify
the game's temporary-bag API behavior.

**Read-only.** One whole snapshot of a character for the character page:
every item in every bag with its augments, gil, job levels, what is equipped, and key items.
It reads what the client already holds; nothing is ever sent.

```
//charsync            write a snapshot now and say what it held (also: //cs)
//charsync roe        RoE observation dates and completion-page coverage
//charsync passive    which login/zoning packets have arrived (zones, monstrosity, MMM, crafts, title)
//charsync warps      how many home points, survival guides and waypoints the client says are set
//charsync warps have|missing [home|guides|waypoints]   which ones, by place name
//charsync status     all saved capture dates and refresh instructions
//charsync need       what you still have to do in game (menus to open, NPCs to talk to); `need all` shows finished rows too (0.3.12)
//charsync last       what the last snapshot held, without writing another
//charsync points     merits and job points summary (and rewrites points.tsv)
//charsync rema       REMA weapons held, watched currencies, Aftermath level
//charsync progress   quest / mission log pages recorded so far (0.3.0)
//charsync sortie [on|off] separate Sortie temporary-state capture setting (default off)
//charsync box [on|off]   the repo-wide display switch; charsync has no display yet
//charsync version
```

It also writes on load, 10 seconds after login, and 10 seconds after every zone (so things moved in
or out of Mog House storage show up).

Files, per character, in `data/<Character>/`:
- `snapshot.tsv`: the latest snapshot, in ffxi-atlas's **character snapshot schema v1**
  (`docs/CHARACTER-SNAPSHOT.md`, checked by `python -m store.snapshot_schema`). atlas owns the
  format; this addon conforms. Written to `snapshot.tsv.tmp` and then moved into place, so a half
  file is never read.
- Version 0.1.1 omits the decoder's binary `__raw` field from the text `ext` column. The final
  `extdata` column still keeps those exact bytes as hex. A 0.1.0 game snapshot can confuse the
  Atlas validator, so reload and run `//charsync` before pulling it into Atlas.
- `history/snapshot-YYYY-MM-DD.tsv`: the last snapshot of each day, kept `keep_days` days
  (default 60), so atlas can show what changed.

A bag the client cannot read (not bought, or not loaded yet) is written as `enabled 0`: its items are
unknown, not absent. The contributor id in the header is combatlog's (`combatlog/data/contributor.txt`)
when there is one, so one install is one contributor; otherwise charsync makes its own.

ffxi-atlas `store.pack pull` copies `snapshot.tsv` into the character pack. Log: `data/charsync.log`.
Offline test: `lua5.1 tools/test-charsync.lua`.

## Since 0.2.0: points and rema live here

The retired `points` and `rema` addons' work now runs in charsync, from the same bag reads, each step
isolated so one failing never stops the snapshot. Same file formats, now in `data/<Character>/`:
- `points.tsv`: merits and job points (written with every snapshot; the merit bank line in `//charsync points`
  needs the Merits menu opened once).
- `rema.tsv`: every Relic / Mythic / Empyrean / Aeonic weapon copy in a readable bag.
- `currencies.tsv`: every numeric field of the last 0x113 / 0x118 (open both Currencies pages). On first
  load it carries over rema's old `rema/data/<Character>/currencies.tsv` if there is one.
`rema_weapons.lua` is generated by ffxi-atlas (`src/market/rema_lua.py`); do not edit it. rema's box and
`points capture` are gone. Switching over: `//lua u points`, `//lua u rema`, remove both from init.txt,
`//lua l charsync`. Offline tests: `tools/test-points.lua`, `tools/test-rema.lua`, `tools/test-charsync-glue.lua`.

## Since 0.3.0: quest and mission recorder

`progress.tsv` holds the newest raw copy of every incoming 0x056 packet (the client's quest and mission log
pages), one row per page type: `captured, packet, type, size, hex`. Every change is also appended to
`progress-history.tsv` (rolled at 512 KB), so a completion shows up as a diff between two copies of one page.
**Nothing is decoded here**: which bits mean "completed" is what this recorder is for, and ffxi-atlas decodes from
evidence later (`docs/PROGRESS-LOG.md` owns the format). The client only sends a page when its menu opens, so
open the Quest and Mission menus and click through every category, then `//charsync progress` lists what was
recorded. Read-only: it never asks the server for anything.

## Since 0.3.3: capture status

`//charsync status` (or `//cs status`) reads saved captures and prints:

- Snapshot capture time, carried bag contents with their original times, and unread bags.
- Each Currencies packet's saved date (date precision only), including a missing page.
- Raw progress page count and saved-change timestamp range.

It gives refresh instructions: `//charsync` for inventory (enter the Mog House
to refresh accessible storage), both Currencies pages for currency facts, and
Quest/Mission categories for progress. Unavailable wardrobes remain unknown.
Unchanged progress pages keep old timestamps, so these are not last-menu-visit
times or decoded completion claims. Status does not rescan inventory, rewrite
captures or request server packets. The cross-addon checklist remains `//ck`.

Offline checks: `tools/test-charsync-status.lua` and
`tools/test-charsync-status-command.lua`, plus `tools/test-charsync.lua`.

### 2026-10-10: Charsync 0.3.4 — read-only RoE evidence (#76)

Records of Eminence is a core planning input for progression, worthwhile rewards, and relevant quest/mission context. Charsync now passively records incoming 0x111 active-objective/progress packets and 0x112 completion pages (Order 0–3) into per-character `roe.tsv`; changed bodies append to size-capped `roe-history.tsv`. These use the five-column raw progress TSV shape, but `type` means RoE page Order, with active packet type 0. Packet layouts come from installed Windower `libs/packets/fields.lua`; no objectives are accepted, cancelled, or requested.

`//cs roe` and `//cs status` list last-observed local timestamps and completion coverage out of four pages. Missing pages remain unknown; dates do not certify all objectives are available or rewards collected. Unlike quest `progress.tsv`, RoE timestamps refresh even for unchanged observed packets. Raw evidence is retained; objective names, rewards, repeatability, and mission relationships still need mapped sources and validation.

18 offline recorder checks and 6 command checks passed; all seven Lua files passed syntax. Deployed by name; in-game verification pending. Reload `//lua r charsync`, open the Records of Eminence menus, then run `//cs roe`. A known objective completion will provide a controlled before/after check; the agent reads the saved files directly. Player captures are never committed.
### 2026-10-10: Charsync 0.3.5 — passive Mastery Rank (#91)

Local incoming 0x01B Job Info supplies the unsigned-byte Mastery Rank at zero-based offset 0x66 (installed Windower fields.lua). This is separate from per-job Master Level. The recorder ignores injected packets and chat senders. It requests nothing.

`mastery.tsv` retains captured local time, packet, rank, size and whole raw hex. First observation and rank changes append to size-capped `mastery-history.tsv`; unchanged observations refresh the latest date. A zero value is an observation; no packet means unknown. Files persist across reloads and are kept separate from inventory snapshots.

`//cs mastery` and `//cs status` show saved rank and date. Reload `//lua r charsync` to enable the deployed code. Natural Job Info traffic will populate it; retail comparison and Atlas pack ingestion are pending. 15 core plus eight real-handler checks passed, with status and RoE regressions passing.

## Warp unlock bitmasks (0.3.13)

Incoming 0x063 with order 6 (byte 5) carries 128-bit masks for home points (zero-based 0x08), survival guides (0x18) and waypoints (0x28). It arrives around login and zoning and when a home point or survival guide menu opens, so no click is needed. Charsync keeps the newest whole packet in `warps.tsv` (same raw shape as `mastery.tsv`) and appends a line to size-capped `warps-history.tsv` only when a mask changes; the header's sequence number and bytes after 0x38 (telepoints, maws, eschan portals: not checked) do not count as changes. `//cs warps` prints the counts.

`warps.tsv` holds the raw packet (bit numbers). This package ships no place-name table, so `//cs warps have|missing` lists the bit numbers ("bit 9"). Names will be added once they are confirmed from our own captures.

## Passive captures (0.3.13)

Packets the client sends by itself at login or zoning are kept raw in `passive.tsv` (newest copy of each, header sequence number ignored; a change appends to size-capped `passive-history.tsv`): 0x008 visited zones, 0x063 orders 3 and 4 monstrosity, 0x0AD Moblin Maze Mongers, 0x062 crafting skills, 0x061 player info and title. The player does nothing; `//cs passive` lists which have arrived, so a setup screen can show "captured" without asking for a click. The packet list comes from the XIchecklist add-on's handlers, and each of these arrived in our Harness captures on every zone-in (3 characters, 2026-10-17). What each one means is that add-on's claim, not decoded or verified here.

## Temprix progress capture (0.3.6)

Passive recording is OFF by default; turn it on with `//cs temprix on`. Once on, speak to Temprix and check your Aeonic progress normally; raw menu/dialogue evidence goes to `data/<Character>/temprix.tsv`. `//cs temprix` shows status; `//cs temprix off` / `on` save the preference. Sessions last up to two minutes; contextual text can include nearby chat. Nothing is sent or blocked. After deployment, reload with `//lua r charsync`. See `docs/temprix-recorder.md` in the source repo.

Each Temprix menu packet (0x034) is also decoded into kill counts for Escha - Zi'Tah (25 NMs), Escha - Ru'Aun (31) and Reisenjima (28): `//cs temprix progress` prints them, `temprix-progress.tsv` keeps the newest packet and `temprix-progress-history.tsv` gets a line when any parameter changes. **Hypothesis**: menu parameters 1-3 are kill bitmasks (popcounts matched one character's real progress on 2026-10-17/18 and one new kill flipped exactly one bit). ## REMA step tracker, all families (0.3.15)

**Release note (0.3.24):** the REMA and Magian step lists (`rema_paths.lua`, `magian_paths.json`, `magian_paths.lua`) are not part of the release package, because they were generated from wiki pages; without them `//cs rema path` says the lists are not included yet, and everything else (snapshot, points, currencies, REMA weapons held, progress capture) works as before. A developer checkout still has them.

`//cs rema path` lists every step still ahead for each REMA weapon you hold; `//cs rema path Chango` does one named line (held or not). One model covers Relic, Mythic, Empyrean, Ergon, Aeonic and Prime: `rema_paths.lua` is GENERATED by ffxi-atlas (`src/market/rema_paths.py`, from the weapon-step store and the cached BG-Wiki category pages) and `remapath.lua` ticks the steps against what charsync already reads: the REMA weapon you hold (stage), `snapshot.tsv` (items, key items), `currencies.tsv`, and the Temprix reading for Aeonic's Geas Fete step. Marks: `[x]` done, `[ready]` needs met, `[ ]` blocked, `[?]` no data source (never shown as not done), `[gap]` the project cannot read that stage yet (Relic 75-99 and Mythic 90-99: Trial of the Magians, pages not cached). Aeonic's Scintillating Rhapsody / Temprix / Geas Fete / delivery steps come from a player's 2026-10-18 summary of the BG-Wiki Aeonic page, which is not in the cache, so they print `(not in cache)`. Oboro 99->119->119 III steps are shared per family; the Afterglow route is listed as a separate step. Offline checks: `tools/test-charsync-remapath.lua`.
