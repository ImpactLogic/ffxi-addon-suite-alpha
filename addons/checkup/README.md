# checkup

**Read-only.** One command that says which facts the other addons hold are missing or old, and
which recorders stopped writing. IDEAS #51 (setup checklist) and #43 (addon health).

```
//checkup (//ck)       everything: setup facts, recorders, recent errors, installed versions
//checkup todo         only what needs doing
//checkup box [on|off] the "todo" list in a box
//checkup version
```

It reads the files in the Windower addons folder and nothing else:

| Check | File read | Old after | What to do |
|---|---|---|---|
| Ionis coalitions | `buffbox/data/<Char>/coalitions.tsv` | 14 days | ask the six Civil Registrars "The State of the <name> Coalition" |
| Merits and job points | `charsync/data/<Char>/points.tsv` | 7 days | load charsync; it saves on load |
| Currencies | `charsync/data/<Char>/currencies.tsv` | 7 days | open the Currencies menu, both pages |
| REMA weapons | `charsync/data/<Char>/rema.tsv` | 7 days | `//charsync` |
| Chat recorder | `ffxilogger/data/chatlog_<Char>_<UTC day>.jsonl` | not today | is ffxilogger loaded? |
| Combat recorder | `combatlog/data/<Char>/combat-<day>.tsv` | not today | is combatlog loaded? |
| Bazaar recorder | `ffxibazaar/data/bazaar_<Char>_<UTC day>.jsonl` | not today | is ffxibazaar loaded? |
| Errors | `<addon>/data/<addon>.log` | an ERROR in the last 7 days | read that log |

Not tracked yet, because their wording has not been recorded (evidence rule): nation rank (Signet),
mercenary rank (Sanction), campaign medal (Sigil).

After login it prints the setup items that need doing, once, 30 s in (`on_login` in settings).
It can't tell whether an addon is loaded: a combat recorder with no file today may just not have
fought yet. Log: `data/checkup.log`.

## //setup: modules ticked like check boxes (0.3.0)

`//setup` (or `//ck`) lists the modules in `packs/` as `[x]`/`[ ]`. `//setup tick story`, `//setup untick endgame`,
`//setup preset new|endgame|levelup|multibox`, `//setup apply`, `//setup skip`. A module is a list of parts (add-on,
optional box, command word); a part shared by several ticked modules loads once, and unticking only hides boxes
no other ticked module needs. Nothing is ever unloaded, and recording is never a module: it stays `//rec`.
Ticked modules are re-applied 30 s after login (`setup_apply_on_login`). Untested in game: `lua l` on an
already-loaded add-on may reload it. Offline test: `luajit tools/test-setup.lua`. Design: plans/setup-packs-2026-10-17.md.

**Base layer (`packs/all.txt`, `always: yes`):** the passive collectors (charsync today) count as ticked for every player,
cannot be unticked, and are what `//setup apply` and the login re-apply load first. Evidence recorders are not in it (`//rec`).

**Requirements:** an add-on that cannot work without another declares `_addon.requires = 'a;b'`; `//setup` loads those too
(transitively). `uses` (registry column) means "works without it". Checked 2026-10-17: battlelines, enmitylines and buffbox
parse live packets and read no recorder files, so none of them has a hard requirement today (enmitylines only hands totals
to the `enmity` recorder through a command that does nothing when it is absent). `registry/addons.tsv` has `requires`/`uses` columns, validated by `tools/registry.py`.

`//ck addons [all|automation|word]` (0.2.0) lists every addon and fork from the registry (`registry.lua`, generated by `python tools/registry.py --write`, which also copies it here): status first (proven, not confirmed in game, or the date it was last seen working in game; grouped into launch, preview and a collapsed private count; `//ck addons all` expands everything, `//ck addons automation` lists the automation add-ons, any other word searches every group), installed version, role. Read-only. Regenerate and redeploy checkup after editing `registry/addons.tsv`.

`//ck depart` (0.3.0, IDEAS #41) is a read-only departure check for the character you are on: zone, free slots in Inventory, Satchel, Sack and Case (LOW below `depart_low`, default 5; FULL at zero; a bag the client cannot read is "unknown", never ok), any setup facts or recorders that need doing, and your own `depart_manual` reminders (settings.xml, free text) printed as CHECK yourself. It does not check supplies or the other character's zone yet (that needs Convoy status). Offline-tested only; reload with `//lua r checkup`.
